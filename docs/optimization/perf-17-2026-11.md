# Fewer memory hops (`claude/perf-17`): the upper bound is small, nothing implemented

Question of the campaign: json and graph spend their wall time in cache misses ([perf-16-2026-11.md](perf-16-2026-11.md)); would an `ArrayList`
without a separate `RefArray` object (small elements inline in the list object, or one allocation for list and storage) remove enough of
them to justify rewriting the stdlib, the emitters and `RcOpt` conventions around `ArrayList.array`?

## Measurement: an upper bound without touching the compiler

`bench/json/json.kt` with its three `ArrayList` uses (`JArr.items`, `JObj.keys`, `JObj.vals`) replaced by a hand-written `SL<T>` that stores up to
four elements in fields `e0..e3` of the list object itself and spills into an `ArrayList` beyond that (every JSON list of the benchmark has at most
four elements, so this is the best case of the inline-storage candidate: one object per list, no `RefArray` at all). Same output, same tree.

| | json (ArrayList + RefArray) | json (`SL`, inline elements) |
|---|---:|---:|
| instructions (callgrind) | 3.598 G | 3.815 G (+6%) |
| D1 read misses (cachegrind, 32 KiB, 4 MiB LL) | 17.9 M | 19.3 M (+8%) |
| user time, median of 5 | 1.121 s | 1.068 s (-5%, inside the noise of this machine) |
| peak RSS | 85 MB | 87 MB |

Removing the hop did not remove misses: the list object grows from 32 to 64 bytes (header, count, four slots, the spill pointer), so a walk
still touches about as many lines, and the `when` over the index adds instructions. The merged-allocation candidate (list object and storage in one
block) would not shrink the data either, and it needs an "embedded object" flag in the free path and a replacement protocol when the storage
grows. With a measured ceiling of about 5 percent in time for the best case, a change of every `ArrayList` operation (`add`, `removeAt`,
`sort`, iterators, `subList`, `toArray`, the borrowed-read conventions of `RcOpt`, the LLVM and C emitters' array fast paths) is not justified.

## Not measured

Value embedding of fields of final, never shared classes (a `JStr` holding its `String` inline, a `Node` holding its edge list) needs an escape
analysis of the field's object; no cheap experiment exists, and it does not apply to the collections, which are the hop-heavy part.

## Result

No code change on this branch. The remaining wall-time gap of json and graph is not one hop that can be removed locally; it is the sum of the object
header (16 bytes), the count updates on every traversal, and the separate objects of the object model, which only a different representation of
collections of objects (unboxed element storage) would change.
