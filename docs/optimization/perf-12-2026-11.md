# fannkuch and spectralnorm against Rust (`claude/perf-12`)

Same host and method as [perf-11-2026-11.md](perf-11-2026-11.md): C backend, `-O2`, instructions = `valgrind --tool=callgrind` totals,
programs linked with an `-O2` runtime. "Before" is the `claude/perf-11` toolchain (origin/main c2359c8).

## Where the extra instructions were

* **spectralnorm** (20.0 G against 12.5 G): the inner loop was 17 instructions: `for (i in 0 until N)` was emitted as the exact counting loop
  (`(uint64)last - (uint64)cur <= step`, `cur = (int)((int64)cur + step)`): five instructions of loop control with a sign extension of the
  index that the C compiler cannot remove, because the wrapping `(int)` cast hides the fact that the counter never wraps.
* **fannkuch** (20.7 G against 9.8 G): the loops of the program index arrays of the constant size 11, but
  (1) the cached length was read from the object (`mk_array_length`), so every bounds test was a compare with a register and nothing folded, and
  (2) bounds-check hoisting versioned the flip loop (about 2 iterations per run, 278 M runs): a guard of 11 instructions, the unrolled
  copy with its prologue and epilogue, next to the original loop: about 30 instructions per run more than the checked loop costs.
  Rust's `[usize; 11]` has constant bounds, so none of this exists there.

## Changes (general, each with a switch and a test, compiler/testdata/loops_const_arrays.kt)

* **plain loops** (`-Xno-plain-loops`, CEmitter): `for (i in a until b)` over `Int` / `Long` without a step is emitted as
  `for (; cur < last; cur++)`. `cur < last <= MAX`, so `cur + 1` cannot overflow; the C compiler sees a non-wrapping signed induction
  variable and widens it / drops the distance arithmetic. Descending, inclusive and stepped loops keep the exact form.
* **constant array lengths** (`-Xno-array-const-len`, ArrayLen): the cached length of an array local made by `mk_array_new_<kind>(<constant>)` is that
  constant; bounds tests compare with an immediate and fold with loop bounds.
* **versioning skips constant-length arrays** (`-Xno-range-check-const`, RangeCheck): an access whose cached length is a constant is neither
  tested by the guard nor turned unchecked (the immediate compare is cheaper than the guard plus the second loop); loops over arrays of unknown
  size are versioned as before (spectralnorm, `mulAv` on parameters).

## What is left

* **fannkuch 1.40x**: 1.1 G of the 13.7 G is the `memmove` call the C compiler makes of `perm1[i] = perm1[i + 1]` (a library call for an 11-element
  shift); the outer permutation step costs about 35 instructions per flip run. `-fno-builtin-memcpy` would take 0.8 G of it but is a global compile
  flag.
* **graph 2.36x**: unchanged and structural, see [hashmap-graph-2026-11.md](hashmap-graph-2026-11.md) (object header, reference counts, cycle
  candidates, `ArrayList` object plus array per node).
