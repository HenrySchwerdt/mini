# Binary size against Rust (`claude/size-1`): already smaller, no change needed

Measured on origin/main 14632d8, Linux x86-64: mini with `minic build -O2 --backend c` (the standard release build: function and data sections,
`--gc-sections --strip-all`, see [linux-size-2026-11.md](linux-size-2026-11.md)); Rust 1.97 with `rustc -C opt-level=3 -C codegen-units=1 -C strip=symbols`
(the `cargo --release` profile plus `strip`; the benchmark sources `bench/*/*.rs`).

A size-tuned Rust build (`-C opt-level=s -C panic=abort -C lto=fat -C codegen-units=1 -C strip=symbols`) is still 291 688 (binarytrees),
296 984 (json) and 303 592 bytes (wordcount): about 4 to 7 times the mini binary. The standard library of Rust (formatting, panic
machinery, the allocator front end) is what stays in a stripped hello-world; mini links only the runtime objects that the program reaches.

## Where the bytes are (`nm --size-sort`, unstripped builds)

* hello: the runtime is the whole program: `mk_small_refill` 782, `mk_alloc_sized_site` 757, `mk_small_cache` 648 (bss), the string and
  print functions 100 to 500 each. About 6 KB of the file are ELF structure (dynamic symbols, relocation sections, the page alignment of
  four segments).
* `stdlib_regex`: the program's own code dominates: `mkh_user_main` 15 KB, the regex parser (`parseSequence` 9 KB, `parseClass` 2.5 KB),
  `Regex.replace`, three string literal blocks of 6 KB, 3 KB and 2.7 KB, `uppercase` 3.3 KB; the runtime is about 25 KB of it.
* `coroutines_async`: 70 closure classes (`$closure...invoke`, 1 to 4 KB each) and the coroutine machinery; `mk_cycles_collect`
  (2.2 KB) is linked because coroutine objects are cycle candidates.

## Outcome

The target (a binary no larger than Rust's) is met by a factor of 4.4 to 11 on every benchmark and by a wide margin on the typical programs, so no
change was made. The remaining candidates are small and each has a cost: `-Os` for the runtime saves about 4 KB of 117 KB of code and costs
speed (linux-size-2026-11.md); `-z noseparate-code` / `-z norelro` save 4 KB and 1 KB but weaken the default hardening; `-no-pie`
gives up ASLR. Page alignment of the segments, not code, sets the size of the smallest programs (hello: 12 KB of code, 18.9 KB file).
If the size of hello-world should shrink below the 14.5 KB of November 2026 (`linux-size-2026-11.md`; the runtime has grown by the
threads, cycle collector and string fast paths since), the lever is the runtime: the thread and formatting parts are already linked only on
demand, `mk_small_*` and the string allocation functions are what is left.
