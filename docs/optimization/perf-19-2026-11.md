# String temporaries in concatenation and appends (`claude/perf-19`)

strbuild (bench/strbuild): part A appends ints, chars and literals to one `StringBuilder` (12 M iterations), part B builds 6 M short strings with
`"item-" + i + ":" + (i * 7)`. It ran at 1.20x Rust in wall time with about 32 M releases.

## Where the temporaries came from

Generated C of the old build, part B, per iteration: `mk_string_from_int(i)`, `concat("item-", t1)`, `concat(t2, ":")`, `mk_string_from_int(i*7)`,
`concat(t3, t4)` = five heap strings, four of them released at once, plus the result. Templates (`"$a$b"`) were already one `mk_string_concatN` call, but
a chain of `+` was lowered as one call per `+` (the IR has a `plus` call, not a template), and in both forms every Int / Long / Char piece first became a
string of its own. Part A: `sb.append(i)` / `append(',')` are already direct runtime calls without a temporary (`mk_sb_append_int` writes the digits into
the buffer); `sb.append("item")` called the `CharSequence` overload (virtual-looking, `return this` retained and released, never inlined because the body
had an early `return` that is not a tail return, which the inliner requires).

## Changes

1. **Flattened `+` chains** (compiler/lower/src/Ir2MirCalls.kt, `stringPlusOperands`): a left-nested chain of standard `String.plus` calls is lowered like
   the template of its operands (same evaluation order, one concatenation of up to six pieces per call).
2. **Numbers written in place** (Ir2MirExpressions.kt `stringConcat`, runtime/src/string.c `mk_string_concat_m3..m6`): an Int / Long / Char piece stays
   a number; `mk_string_concat_mN(mask, s0, v0, s1, v1, ...)` takes two bits per piece (string / decimal digits / char), measures once and writes the
   digits straight into the result (narrow result when every string is Latin-1 and every char < 256, otherwise wide). No string is made for a number.
   Two pieces with a number still use the old form. `-Xno-concat-numbers` switches both (1) and (2) off.
3. **`mk_i64_length` without a loop** (bit length times 1233 >> 12 and one table compare; checked against `snprintf` for -3 M..3 M, the powers of
   ten +-2, and the extremes). It serves `mk_string_from_long`, `mk_sb_append_int` / `long` and the new concatenation. `copy_short` instead of `memcpy`
   for the pieces.
4. **`StringBuilder.append(CharSequence?)`** is written as if / else with tail returns (the slow part in `appendOther`), so the inliner expands it: a call with
   a String argument is one `mk_sb_append_string` and no retain / release of `this`. (A separate `append(String?)` overload with `@JvmName` worked too, but
   the 0.7 seed compiler does not honor `JvmName` on members and hit a duplicate C symbol.)

Test: compiler/testdata/concat_numbers.kt (chains and templates with Int / Long / Char / null / wide pieces, Int and Long extremes, evaluation order of
side effects, `+=` in a loop, the StringBuilder overloads); its output is identical with `-Xno-concat-numbers`.

## Result

| benchmark | before | after |
|---|---:|---:|
| strbuild, callgrind instructions | 10.328 G | 5.607 G (-45.7%) |
| strbuild, wall time (bench/walltime.sh, median of 7, C backend) | 1.20x Rust | 0.60x Rust (0.444 s vs 0.745 s Rust) |
| json | 3.643 G | 3.580 G |
| wordcount | 9.076 G | 9.036 G |
| binarytrees | 11.246 G | 11.246 G (identical) |
| graph | 2.109 G | 2.178 G (+3.2%, from the merged main: `MK_CYCLES_ADD` of the inline allocation path (threads-2); the generated C of graph differs from perf-18 only there) |

The remaining cost of strbuild: `mk_string_concat_m4` (about 330 instructions per call: two passes over four pieces and the allocation), `mk_i64_write8`
and the result string's allocation and release.

## Not done

- **Stack / arena strings for non-escaping temporaries**: the result `s` of the concatenation in part B only feeds `length` and `charAt`. Making it a
  stack object needs an alloca-style buffer in both backends (the C emitter and the LLVM lowering have no such construct; MIR cannot declare one), plus
  an escape check on every use. A per-thread scratch string was rejected: two live temporaries (or a callee that concatenates) would overwrite each other.
  What it would save is the allocation and the release of one string per iteration (about 10% of strbuild).
- **Release fast path for strings**: already there (`mk_release` frees a String / boxed Int block directly when not armed, buffered or prefixed).
- **The node retain per word in wordcount**: not touched.
