# json and wordcount against Rust (`claude/perf-11`)

Same host and method as [rust-gap-2026-11.md](rust-gap-2026-11.md): C backend, `-O2`, instructions = `valgrind --tool=callgrind` totals
of the full-size runs, programs linked with an `-O2` runtime. "Before" is `origin/main` (c51b5d3) built with the same stage0. The VM is shared
and loaded (other jobs, load average 10-20): wall times below are medians of 7 runs taken while a test suite ran, so they are rough; the
instruction counts are the reliable column. No hardware counters are available (`perf` does not work in this VM).

## Changes (all general, none benchmark specific)

* **`exact-is`** (`-Xno-exact-is`, opt/ExactIs.kt): `x is C` where no class of the linked program has `C` as superclass is
  `o != null && o->type == &C_ti` instead of a walk up the superclass chain (`MirExpr.IsInstance.exact`, `(isx ...)` in the MIR text; the
  LLVM emitter reuses `exactTypeCheck`). The leaves of a sealed hierarchy (`when (j) { is JNum -> ...}`) are the typical targets: json
  `walk` tested six classes in a row, 6 percent of its instructions were the walks. Not applied to classes that a C function of the program
  may return a subclass of (`@CSymbol external fun f(): Base`, found by `cinterop_typecheck_family`): C code can make objects of a type
  info the MIR does not list.
* **Cold `noreturn` failure paths** of the inline string / array accessors (C prelude): the paths always end in `mk_panic`, declared so
  the C compiler can keep loop-invariant loads in registers across the bounds test.
* **`substr-key`** (`-Xno-substr-key`, opt/SubstrKey.kt), the deferred substring-free lookup. After inlining, a local
  `w = s.substring(a, b)` whose every use is the key of `HashMap.findNode` or `HashMap.put` is not made: lookups call
  `findNodeRange(s, a, b)` (hash and comparison read `s` in place: `mk_string_hash_range`, `mk_string_equals_range`), `put` calls
  `putRange(s, a, b, v)` (the key String is made only when the entry is new), and a `put` that follows a lookup of the same range with
  nothing in between that could change the map (no call, store or allocation but boxes: checked on the MIR) receives the node found
  (`putRangeAt`) and needs no second lookup. Proof obligations: strings are immutable, so the characters are those `w` would hold as long as
  `s`, `a`, `b` keep their values: operands that are locals never assigned are used as they are, all others are copied into fresh locals
  where `w` was declared; any other use of `w` (passed, stored, returned, captured, printed) leaves the local alone; the range test stays at the
  original statement as `kotlin.text.checkSubstringRange` (same `IndexOutOfBoundsException`, same place, before anything later). The helpers are
  kept by the pruning (`MirLink` / `Devirt`, `companionsMissing`) when `substring` and `findNode` / `put` are live. Test:
  compiler/testdata/substr_key.kt (escaping keys, bad ranges, operands changing, `remove` / `clear` between lookup and put, wide strings).
* Runtime: `mk_string_hash_range` / `mk_string_equals_range` (short ranges without the unrolled loop), runtime test in test_string.c.

## What is left

* **wordcount**: 1.05x in instructions. The remaining gap is memory (three dependent cache lines per lookup, as in
  [wordcount-gap-2026-11.md](wordcount-gap-2026-11.md)).
* **json (target 1.1x not reached)**: 1.25x in instructions, more in time: the user time per instruction is about 1.3x Rust's. The instructions
  are the object model, not the scanning: the character loops (`parseString`, `walk`) are as long as Rust's; what is left is reference counting
  and the allocator (release of a tree: about 1000 M of 3880 M, 54 instructions per freed object, 11 M `mk_release` calls with 8.5 M
  mispredicted conditional branches in the cache simulation) against `malloc`/`free` of larger blocks (a Rust `Vec<J>` keeps its elements
  inline; Mini has a `JArr`, an `ArrayList`, a `RefArray` and one object per element). Nothing cheap and general is left in the generated code;
  an inline small-object allocator in the C prelude or unboxed element storage would be the next steps. Tried and not kept: loop
  unswitching on the Latin-1 flag of a string (`-mllvm -enable-nontrivial-unswitch`: -2 percent, a global flag change).
* **graph**: +0.35 percent is `ArrayList.modCount` from main (c51b5d3), not from this branch.
