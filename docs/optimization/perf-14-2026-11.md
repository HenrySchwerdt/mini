# Release and teardown (`claude/perf-14`): findings, no change kept

Starting point: `claude/perf-13` (58fa550). Release and teardown are 31 percent of graph and 26 percent of json
([perf-13-2026-11.md](perf-13-2026-11.md)). The per-line callgrind profile of graph (2.10 G) shows that this cost is spread over many
small items, none of which is a cheap general win:

| item (graph) | instructions | note |
|---|---:|---|
| `ref_array_dispose` | 170 M | about 30 per element; elements that are `ARMED` (every `Node`) always call `mk_release` |
| cycle candidates: `cycles_candidate` 48 M, `slots_put` 78 M (25 M of it table growth), `release_buffered` 50 M | ~175 M | one buffer entry plus one hash-table slot per candidate (1 M nodes) |
| `mk_release` / `mk_release_armed` / free path | ~300 M | the armed path is one hook call, `MK_DEEP()`, the dispose chain, then the free |
| generated `ArrayList.dispose` | 290 M inclusive | field release of the backing array: `mk_release` -> `release_armed` -> `free_dead` -> `ref_array_dispose` |

## Tried and dropped

* **Skip `kotlin.Any` in the dispose chain of `free_dead`** (two iterations become one): json +0.2 percent, graph 0, binarytrees -0.6 percent.
  The extra compare costs what the iteration saved.
* **Direct call of `mk_release_armed` from `mk_release`** (no hook): the code of the armed release would be linked into every program,
  including hello-world (the size must not grow), so the hook stays.

## Why the other candidates were not attempted

* **Cheaper cycle-candidate bookkeeping with a header bit**: the roots buffer needs the index of an object to remove it when it dies while
  buffered (`slots_take`). The 8-byte header has no room for a 21-bit index. Letting a buffered object linger as a zombie until the next
  collection would take the hash table away, but delays freeing its block (blocks reused LIFO stay cache-hot today) and changes the memory
  behaviour that the `stress-rss` suite checks; it needs its own measurement campaign.
* **Bulk release of the `ArrayList` backing array**: the array is released by the generated field release of `ArrayList`; a shortcut needs a
  hand-written dispose for `ArrayList` (or an annotation that makes the compiler call a runtime function for a private, never shared
  field), and the depth control of `mk_release` (`MK_DEEP()`) must stay in force for the elements.
* **Per-class generated release code**: the dispose functions are already per class; the generic part is the type-chain loop, measured above.

## Next steps (not started)

1. A "private unique reference" field annotation so that the generated dispose frees the object directly (no count, no candidate test) and
   calls a bulk release for reference arrays: needs `RcOpt` and both emitters.
2. Zombie buffered objects (above), with the table of slots replaced by a lazily compacted list.
