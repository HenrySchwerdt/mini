# The allocation volume counter, read sets of borrowed results, the LLVM column (`claude/perf-20`)

## 1. graph: the +3.2% of perf-19

perf-19 measured graph at 2.178 G (perf-18: 2.109 G) and attributed it to `MK_CYCLES_ADD` (the relaxed-atomic add that threads-2 made of the allocation
volume counter). Measured with the same generated C against the runtime of three commits (callgrind, instructions):

| generated C | runtime | graph |
|---|---|---:|
| perf-18 emit (plain `+=`) | perf-18 (0cdb1a9) | 2.100 G |
| perf-18 emit | perf-18 + threads-2 (9c5445f) | 2.087 G |
| perf-19 emit, relaxed atomic add | | 2.178 G |
| perf-19 emit, plain global `+=` | | 2.119 G |

So the runtime side of threads-2 costs nothing here; the atomics in the *inline allocation path of the generated code* cost 59 M (the compiler could not
keep the load/add/store as one `add [mem]` and reordered less), and the rest (about 30 M) was code generation of `mkh_user_main` with the cold bounds-failure paths of
`ArrayList.get`/`set` (each built its message with a concatenation of two numbers inline).

Changes:
- **Per-thread counter** (`MkSmallCache.cycles_bytes`): the inline allocation and the runtime's small-object path add to the thread's own counter with
  a plain add (`t->cycles_bytes += n`; no data race for ThreadSanitizer, the counter is thread-local). The collector reads the counter of the thread that runs
  it plus the global counter (`mk_cycles_alloc_bytes`, now written only by the large-object path and by a thread that exits: `flush_all` adds its share), and
  resets its own. A collection runs only when no Kotlin thread runs, so every live share but the caller's is zero or already in the global counter.
- **Bounds-failure messages in one helper**: `mini.internal.throwIndexOutOfSize(index, size)` / `throwIndexOutOfLength(index, length)` build
  `"index: $index, size: $size"` themselves; the 14 checks of ArrayList, the abstract collections and StringBuilder call them with two Ints.

Result: graph 2.178 G -> 2.132 G (-2.1%). The goal of 2.109 G is **not** reached (+1.1%); the remainder is a code-generation difference in
`mkh_user_main` that I could not attribute to a single change (the same source with `-Xno-concat-numbers` gives 2.156 G; the runtime is not involved, see the table).
`runtime/run_tests.sh` (thread tests under ThreadSanitizer) passes.

## 2. wordcount: the node retain per word

`val c = m[word]; if (c == null) m[word] = 1 else m[word] = c + 1` becomes, after the substring-key pass, `t = findNodeRange(...)`, `c = t.value`,
`setNodeValue(m, t, v)` / `putRange(...)`. `findNodeRange` is `@ReturnsBorrowed`; RcOpt treats the call result as an alias of "whatever the function reads" and
gave it the sensitivity *unknown*: any store into any field ended the alias, so the node got a retain and a release per word because `setNodeValue`
stores into `HashNode.value`.

Now `RcEffects.readEff(cName)` computes what a Kotlin function reads (the fields it loads, array slots through `mk_ref_array_*` reads, transitively through direct
calls; *unknown* for virtual / interface calls, impure runtime calls and `ObjectGet`) and the sensitivity of a borrowed result is that set. For `findNodeRange`
it is `HashMap.table`, `HashNode.hash/key/next` and the array slots, so the store into `HashNode.value` does not invalidate the node. A rehash, `remove`, `clear`
or any store into the table or a `next` link still does. Off-switch: `-Xno-rc-read-sets`.

Test: compiler/testdata/rc_borrow_traps2.kt (word counting through substring keys, `remove` / `clear` / replace-and-rehash while the found value or node is
still used); same output with and without the flag.

| benchmark | before | after |
|---|---:|---:|
| wordcount, callgrind instructions | 9.036 G | 8.564 G (-5.2%) |
| generated C of the loop | `MKH_RETAIN(t)` / `MKH_REL(t)` per word | none |

## 3. The LLVM column of `bench/walltime.sh`

`compiler/bootstrap.sh --backend=llvm-api <dir>` works here (LLVM 18, 8 minutes: stage2 == stage3 byte-identical); `MINIC_API=<dir>/stage3 bench/walltime.sh`
fills the column. It must be built from the sources being measured. Median of 5 pinned runs on the noisy shared machine (seconds):

| benchmark | C | LLVM | Rust | C/Rust | LLVM/Rust |
|---|---:|---:|---:|---:|---:|
| strbuild | 0.582 | 0.608 | 0.941 | 0.62 | 0.65 |
| wordcount | 2.621 | 2.402 | 1.823 | 1.44 | 1.32 |
| graph | 2.186 | 2.139 | 1.387 | 1.58 | 1.54 |
| json | 1.357 | 1.578 | 1.083 | 1.25 | 1.46 |

(The machine is loaded: the minimum column of the script is the more reliable one, and the ratios move by 20% between runs.)
