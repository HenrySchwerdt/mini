# Count updates while traversing (`claude/perf-18`)

## Measured: where retains and releases come from

`-DMK_STATS` builds (every `MKH_RETAIN` / `MKH_REL` calls the runtime and is counted, `retains_noop` / `releases_noop` are NULL / static operands that the
inline fast path of a normal build skips with one test), before this branch:

| benchmark | retains (real) | releases (real) | what they are |
|---|---:|---:|---|
| json | 2.83 M | 14.1 M | every retain is a store into a list or a field (`add`, constructor), the releases are the teardown of 11.2 M objects |
| graph | 9.88 M | 7.0 M | `nodes.add`, `n.out.add`, `queue.add` (a store each) and the teardown; no element load is retained: `list[i]` and the iterator are borrowed reads already (`mk_ref_array_get_b`) |
| strbuild | 2.40 M | 32.4 M | builder appends and string temporaries |
| wordcount | 23.5 M | 25.1 M | 2 retains and 2 releases per word: the node that `findNodeRange` returned and the value `c` read from it |

So the collections' element loads were already free of count updates; the traversal cost is the stores and the teardown. The one pattern with
avoidable retains is a value read from an object that is later stored to in one arm of an `if` (`val c = m[k]; if (c == null) m[k] = 1 else m[k] = c + 1`).

## Cause and change

`RcOpt` keeps a local that aliases a field or an element (`val c = h.v`) without a count while no *event* that can free the old value lies
between its definition and its last use. Positions are linear, so the store in the `then` arm of the `if` above (textually before the use in the `else`
arm) counted as an event "between" the definition and the use, although the two arms are never on one path of execution. It now records, for every use and every
event, the chain of `if` arms it lies in, and an event in a different arm of an `if` than the use does not count (`RcOpt.branchExclusion`,
`-Xno-rc-branch-exclusion`). Uses that a loop extends and assignments keep the old, conservative rule.

`HashMap.setNodeValue` (a statement form of the node update of the substring-key pass: `if (node != null) setNodeValue(node, v) else putRange(...)`)
replaces the call of `putRangeAt` there: the update changes only the node's value, which is what lets the node and a value read from it stay
borrowed up to it, and the heavy insertion path is on the other branch.

Tests: compiler/testdata/rc_borrow_traps.kt (a field alias used after the same arm frees its object, removal and clearing of a list while an
element read before is used, an element stored and the list cleared, a callback that empties the list, a loop that clears the list at the first
iteration: all run under AddressSanitizer in the leak suites, and give the same output with the flag off).
