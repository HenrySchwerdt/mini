Mini 0.5.0: the whole toolchain is native. `mini`, `minic` and the compiler need no JVM, and the compiler compiles itself through C and LLVM.

Install:

```sh
curl -fsSL https://raw.githubusercontent.com/HenrySchwerdt/mini/main/install.sh | sh
mini new hello && cd hello && mini run
```

Try it in the browser: https://henryschwerdt.github.io/mini/ (every example in the docs has a Run button).

## Highlights

**Native project tool `mini`.**
* `mini new`, `build`, `run`, `test`, `check`, `add`, `tree`, `explain`, `doctor`.
* `mini.toml` with path and git dependencies.
* Compiled by Mini itself: about 1 ms to start and ships in the release archive. No JDK, no Gradle.

**`minic` with good diagnostics.**
* Errors read like rustc: `file:line:col`, the source line with an underline, and a summary line. Memory-model errors link to their documentation page.
* `--error-format=json`, `--color`, `--error-limit`.
* New commands: `minic run file.kt -- args`, `minic check file.kt`, `--help` for every command, and "did you mean" for typos.
* Clear exit codes: 0 ok, 1 compile error, 2 usage, 3 internal compiler error.
* A missing C compiler is explained. Generated C is never shown as a raw C error.
* `-O2` is the default. `minic build -g` emits `#line` directives, so gdb and crash reports show your `.kt` lines.

**LLVM backend.**
* MIR to LLVM IR, as text or in memory through the LLVM C API bound in Mini (`minic-native --backend=llvm|llvm-api`).
* `minic-native --run` runs programs with the ORC JIT.
* Now as fast as the C backend, or faster on numeric code: TBAA, the initial-exec TLS model, and no exception test on the fast path of array accesses.

**C interop.** `external` + `@CName`, `CPointer`/`*Var`, `memScoped`, `@CStruct`, `staticCFunction`, `@file:CInclude`/`@file:CLink`, and `@Owned(free=)` for C-allocated memory.

**Performance.**
* A thread-local size-class allocator for small objects and faster arenas: 30–48% faster on allocation-heavy code.
* Inline array accessors, array reads without reference counting where that is safe, and fast integer formatting.
* Against C at -O2: nbody 0.94–1.03x, mandelbrot ~1.0x, fannkuch 0.9–1.2x, binarytrees ~1.2x, spectralnorm ~1.2x.
* Cross-language results (C, Rust, Go, JVM, Kotlin/Native): https://henryschwerdt.github.io/mini/benchmarks

**Language.**
* The overloadable matrix operator `a @ b` (`operator fun matmul`, `@=`). It is built for tensor libraries, and nothing implements it by default.
* Operators with context parameters now work.
* More Kotlin parsed exactly like K2.

**In the browser.**
* `minic` compiled to WebAssembly, together with clang and wasm-ld.
* A playground, notebooks, and Run/Check buttons on every documentation example.
* A notebook-style tutorial: https://henryschwerdt.github.io/mini/learn/

## What is in the release

* `mini-0.5.0-<target>.tar.gz` for linux-x64, linux-arm64 and macos-arm64:
  * `bin/mini`: the project tool
  * `bin/minic`: the driver, with `run`, `build`, `check`, `emit-c`
  * `bin/minic-native`: the self-hosted compiler
  * `lib/libminirt.a` and `include/`: the runtime
  * `stdlib/`: the standard library sources
* `mini-0.5.0-bootstrap-c.tar.gz`: the generated C of the compiler plus the runtime sources. A C compiler alone builds a working compiler from it.
* `SHA256SUMS`.

## Known gaps

* A C compiler (clang or gcc) is still needed at build time.
* No Windows. No coroutines or async IO. No reflection or JSON yet; JSON will be a separate library, `mini-serialization`.
* Programs that use allocator objects (`mini.memory`) do not build on every path yet. The memory checker covers them everywhere.
* `mini check` on projects that are not in Strict mode only checks the first file.
* The repository's own test suite still runs on Gradle/JVM. Moving it to `mini test` is in progress.
