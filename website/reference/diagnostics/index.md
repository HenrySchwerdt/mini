# Diagnostics reference

Every memory-model diagnostic has a stable code. The **code** and the **primary source position** are stable; the message text, labels and `help:` line may change. Errors stop the build (exit status 1); warnings do not, unless you pass `-Werror`.

The pages below are generated by `website/scripts/gen-diagnostics.mjs` from the test corpus `compiler/testdata/memory/` and the output of the real compiler, so they cannot drift from the implementation. Only the prose is hand-written.

## Output format

```text
<severity>[<code>]: <message>
  --> <file>:<line>:<col>   <label>
   <line> | <source line>
          | <caret under the primary position>
  help: <text>

note: <code> (<title>): <link to its page>
```

Every code that was reported is named once at the end with its title and the link to its page. For editors and tools, the released `minic` (the self-hosted one) prints, with `--error-format=json`, one JSON object per diagnostic on stderr (`severity`, `code`, `message`, `file`, `line`, `col`, `endCol`, `label`, `secondary`, `help`, `docs`); `--color=always|never|auto` and `NO_COLOR` control colors and `--error-limit=N` stops printing after N diagnostics.

With `./minic check --brief file.kt` the compiler prints only `line:col: CODE` lines on stdout; this is what the test corpus compares.
