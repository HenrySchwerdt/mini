# M0204: No allocator for an escaping Strict value

<span class="diag-badge error">error</span>

## What it means

A Strict class without `@AllocatedBy` and without a visible allocator uses the default allocator: its objects may be returned and stored, and the owner releases them when it ends. The default allocator cannot be used where an object leaves the owner's thread or its stack frame in a way the owner cannot follow: moved into a thread, owned across the suspension points of a coroutine, or an owner returned from a lambda.

## Minimal failing example

From the test corpus: [`compiler/testdata/memory/default_into_thread.kt`](https://github.com/HenrySchwerdt/mini/blob/main/compiler/testdata/memory/default_into_thread.kt). The corpus expects `12:20: M0204` (the `^` comment in the source marks the column).

```kotlin check=M0204
// REJECT M0204: an object of the default allocator cannot be moved into a thread (a thread needs a ThreadSafe allocator). Spec 2.2a, 7.15
@file:MemoryMode(Mode.Strict)

package memory.default_into_thread

import mini.memory.*

class Box(val v: Int)

fun main() {
    val b = Box(1)
    val t = Thread { println(b.v) }
//                   ^ M0204
    t.start()
    t.join()
}
```

## How to fix

Allocate the object with a `ThreadSafe` allocator (`context(h: Heap)` on the function, `context(Heap()) { ... }` around the call, or `@AllocatedBy(Heap::class)` on the class), or return the allocation itself (`{ Box(1) }`) instead of an owner.
