# M0204: No allocator for an escaping Strict value

<span class="diag-badge error">error</span>

## What it means

In a Strict file there is no default allocator. A value that escapes (is returned, stored, passed as `@Owned`) needs one from a visible `context(...)` parameter or from an `@AllocatedBy` class annotation. Non-escaping values simply live on the stack and need none.

## Minimal failing example

From the test corpus: [`compiler/testdata/memory/no_allocator_escape.kt`](https://github.com/HenrySchwerdt/mini/blob/main/compiler/testdata/memory/no_allocator_escape.kt). The corpus expects `10:26: M0204` (the `^` comment in the source marks the column).

```kotlin
// REJECT M0204: Strict, escaping allocation, no allocator selectable. Spec 2.2, 7.15
@file:MemoryMode(Mode.Strict)

package memory.no_allocator_escape

import mini.memory.*

class Box(val v: Int)

fun make(): @Owned Box = Box(1)
//                       ^ M0204

fun main() {
    println(make().v)
}
```

## How to fix

Add `context(h: Heap)` to the function, wrap the call in `context(Heap()) { ... }`, or annotate the class with `@AllocatedBy(Heap::class)`.
