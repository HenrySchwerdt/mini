# M0110: Violation of the Strict/Managed boundary

<span class="diag-badge error">error</span>

## What it means

A tracked (Strict) value crosses into Managed code in a way the checker cannot follow: it goes into a Kotlin collection, into a field of a Managed class, into a Managed function parameter that is not `@Borrowed`, or Managed code calls a Strict function that takes or returns ownership.

## Minimal failing example

From the test corpus: [`compiler/testdata/memory/boundary_collection.kt`](https://github.com/HenrySchwerdt/mini/blob/main/compiler/testdata/memory/boundary_collection.kt). The corpus expects `14:14: M0110` (the `^` comment in the source marks the column).

```kotlin check=M0110
// REJECT M0110: a Strict object goes into a Managed collection (collections of owned values are P3). Spec 5.4, 7.10
@file:MemoryMode(Mode.Strict)

package memory.boundary_collection

import mini.memory.*

class Box(val v: Int)

context(h: Heap)
fun run() {
    val list = ArrayList<Box>()
    val b = Box(1)
    list.add(b)
//           ^ M0110
    b.free()
}

fun main() {
    context(Heap()) { run() }
}
```

## Compiler output

Generated by running `./minic check compiler/testdata/memory/boundary_collection.kt` (exit status 1).

```text
$ ./minic check compiler/testdata/memory/boundary_collection.kt
error[M0110]: Strict value handed to Managed code
  --> compiler/testdata/memory/boundary_collection.kt:14:14   passed to a Managed function that does not promise to borrow
   14 |     list.add(b)
      |              ^
  help: mark the parameter `@Borrowed`, or wrap the call in a Strict function
```

## How to fix

Build your own container class from owning fields, wrap the Managed call in a Strict function that frees internally, or mark the Managed parameter `@Borrowed` if it really only borrows.
