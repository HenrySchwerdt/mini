# M0112: Owning value in an escaping lambda

<span class="diag-badge error">error</span>

## What it means

A lambda that is not inlined and is not a thread boundary (a closure object) captures an owning value. The closure object retains what it captures and may outlive it. Closures as owners (move capture) are not supported yet.

## Minimal failing example

From the test corpus: [`compiler/testdata/memory/capture_escaping_lambda.kt`](https://github.com/HenrySchwerdt/mini/blob/main/compiler/testdata/memory/capture_escaping_lambda.kt). The corpus expects `13:12: M0112` (the `^` comment in the source marks the column).

```kotlin check=M0112
// REJECT M0112: an owned value captured by a lambda that escapes. Spec 5.5, 7.12
@file:MemoryMode(Mode.Strict)

package memory.capture_escaping_lambda

import mini.memory.*

class Box(val v: Int)

context(h: Heap)
fun later(): () -> Int {
    val b = Box(3)
    return { b.v }
//         ^ M0112
}

fun main() {
    context(Heap()) { println(later()()) }
}
```

## How to fix

Make the called function `inline` (inline lambdas are read like code at the call), pass the value to the code that needs it as an explicit parameter, or read the data you need (`b.v`) before creating the lambda and capture that instead.
