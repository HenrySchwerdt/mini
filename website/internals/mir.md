# MIR

MIR is Mini's mid-level IR (`compiler/backend/.../Mir.kt`). It sits between the Kotlin IR and C: it is typed, structured (`if`, loops, `try`, no basic blocks) and close enough to C that emitting code is mostly mechanical. The backend never sees Kotlin IR, which is what lets it run without the K2 compiler.

## Shape

A module is a list of **classes** and **functions**. Functions are made of statements (`declare`, `assign`, `if`, `return`, `setfield`, `eval`, loops, `try`) over expressions (`bin`, `call`, `rcall` for a runtime call, `new`, `get`, casts, boxing). Types are a small set: `Int`, `Long`, `Boolean`, `Double`, `Char`, `String`, `Unit`, `Nothing`, nullable string, `(obj ...)` for classes and interfaces, and `(boxed <prim>)`. Locals are numbered per function.

## Serialized format

MIR can be written to a text file with `minic emit-mir` and read back, which is how the self-hosted backend gets its input (stage B1, see [Self-hosting](./bootstrap)). The format is versioned (`(mini-mir 1 ...)`), S-expression based, ASCII only, one class, function or statement per line. A test checks, for every test program, that MIR to text to MIR to C is byte-identical to MIR to C.

What to notice:

- `fib` has one extra local, `tmp` 2, that holds the value of the `if` expression. Expression-bodied code is flattened into statements.
- Names carry the C symbol (`kt_fib_AI`, `kc_Counter_Minc`); see below.
- Properties are accessor functions (`Counter.<get-n>`); the emitter inlines calls to default accessors into plain field reads.
- `(vtable - - -)` are the three fixed slots (`toString`, `equals`, `hashCode`), all defaulting to the runtime's `Any` implementations.
- Intrinsics are `rcall`: `println` of an `Int` is `mk_println_int` in the runtime.

Points worth reading in this output:

- `struct kc_Counter` starts with the `MkObject header`, then the fields. `kc_Counter_ti` is the type info. `new` is an allocating wrapper around the constructor-initializer.
- `Int` arithmetic is done on `uint32_t` and cast back, so overflow wraps without C undefined behavior.
- `main` is `mkh_user_main`; the generated `mk_main` calls it and reports an exception that escaped.
- The local `v_c_1` owns one reference and releases it at the end of the scope with `MKH_REL`.

## C name mangling

`Mangling.kt` makes C names injective and collision-free with the runtime:

| Thing | Name |
|---|---|
| `fun main()` | always `mk_main`; the user entry is `mkh_user_main` |
| top-level function | `kt_` + package parts and name joined with `_D`, then `_A` + one letter per parameter: `fib(Int)` is `kt_fib_AI` |
| parameter letters | `I` Int, `J` Long, `Z` Boolean, `D` Double, `C` Char, `S` String, `L<class>_E` object, `Q` prefix for nullable |
| class | `kc_` + package and nested path joined with `_D`: `kc_Counter`; type info `kc_Counter_ti` |
| method / constructor | `<class>_M<name>_A<letters>` / `<class>_C_A<letters>` (plus an allocating `_new`) |
| local, string literal, helper | `v_<name>_<id>`, `kstr_<n>`, `mkh_*` |

Runtime symbols (`mk_*`, `Mk*`) are never produced for user code.
